# memblocks

> 三层记忆：稳定区 / 待办 / 归档。给长期对话用的最小实现。

## 这是什么

一个零依赖的 Python 记忆包，用来替代「把整段聊天历史塞进上下文」：

| 层 | 内容 | 规则 |
| --- | --- | --- |
| **稳定区** | 长期事实（身份、偏好、约定） | 上限 100 条，写满按权重淘汰最老的，并写告警 |
| **待办** | 短期任务 | 带截止日期，过期归档后删除 |
| **归档块** | 对话摘要 | 超 800 字自动拆块 |

没有人物事实、没有时间线、没有自动抽取——那三块修了几轮仍有 bug，不如不做。

## 安装

纯标准库，Python 3.10+，不用 pip。

```bash
git clone https://github.com/gutuxxxxl/-.git memblocks
cd memblocks
python -m memblocks.cli init
```

## 用法

```bash
# 稳定区
python -m memblocks.cli stable add "我在邹城做律师" --tags 身份
python -m memblocks.cli stable add "人设：你是小鲸" --weight 9
python -m memblocks.cli stable list

# 待办（支持「下周三」「一个月后」「十二月二十八号」）
python -m memblocks.cli todo add "给客户回电话" --due 下周三
python -m memblocks.cli todo done --id td-xxxx

# 归档块
python -m memblocks.cli block add --summary "讨论分层记忆方案" --tags 上下文

# 生成注入文本
python -m memblocks.cli inject --query "记忆" --max-tokens 800

# 维护
python -m memblocks.cli janitor --dry-run
python -m memblocks.cli janitor
```

## 稳定区上限

写满 100 条后：

1. 新增照常写入
2. 淘汰**权重最低、时间最老**的一条
3. 写 warn 到 `audit.log`
4. `protected: true` 的人设不参与淘汰

不会直接拒绝写入——拒绝会让人当场卡住。

> 注意：淘汰发生在 `stable_add` 写入时；`janitor` 只在异常情况下兜底，
> 所以它的报告里 `stable_trimmed` 通常是 0，这不是 bug。

## 超长直接报错

单条超过上限（稳定/待办 200 字、块 2000 字）不再静默截断，直接抛 `ValueError`。

```bash
$ python -m memblocks.cli stable add "$(python -c 'print("x"*201)')"
{"error": "稳定记忆 超长：201 > 200 字，请先拆分"}
```

## 快照

每次 `janitor` 前自动快照，保留**最近 3 份**，目录名带 uuid 防同秒覆盖。

```python
store.restore("memories/snapshots/snap-20261031-060000-ab12")
```

## 健壮性

- JSON 损坏不静默：改名为 `.bad-时间戳` 并抛错
- 快照包含全部数据文件
- 块先按 800 字切分，再逐块校验
- 支持中文数字日期：「十二月二十八号」→ 2026-12-28
- 写入加文件锁（Windows `msvcrt` / Linux `fcntl`）

## 性能基线（1000 块）

```bash
python bench.py
```

| 指标 | 数值 |
| --- | --- |
| 建 1000 块 | 0.57s（0.6 ms/块） |
| 首次 `block_list` | 1.56s（冷读 1000 个文件） |
| `inject` 平均 | 76 ms（p95 80 ms） |
| `janitor` | 0.64s |
| 磁盘 | 0.50 MB |
| 块文件数 | 1000 |

结论：

- 1000 块以内，注入 76 ms，完全够用
- 冷读 `block_list` 是瓶颈（文件系统元数据），热读后很快
- 超过 3000 块建议按年月归档，否则冷读会到 4~5 秒

这个基线顺带测出一个 bug：块 ID 后缀只有 4 位十六进制，
1000 个块里撞了 6 个（994 而不是 1000）。已改为 10 位。

## 注入按命中位置取窗口

长块被预算截断时，不再从头截：

- 命中关键词 → 围绕命中位置取窗口（前 1/3、后 2/3）
- 没命中 → 正常从头截

这样「块拆开能搜到，但注不进去」的问题不会出现。

## 记忆星图（行星运转版）

![记忆星图](docs/star.png)

```bash
python -m memblocks.cli star --out memory-map.html
```

打开 HTML 即可，无依赖、无服务器。

**每条记忆是一颗行星**：

| 行为 | 实现 |
| --- | --- |
| 公转 | 各走一条偏心率 0.05~0.21 的椭圆轨道 |
| 速度 | 开普勒式：内圈快、外圈慢（ω ∝ 1/r^1.15） |
| 倾角 | 三层不同，稳定区略后仰、待办居中、归档前倾，形成 3D 层次 |
| 拖尾 | 最近 26 个位置连成淡光尾迹 |
| 轨道线 | 每颗星自己的椭圆轨道，可点底部「轨道」开关 |
| 恒星 | 金色十字星芒，固定在中心，永不衰减 |

三层轨道仍对应三层记忆：内圈稳定区、中圈待办、外圈归档。

遗忘：`R = exp(-天数 / τ)`，越暗越接近遗忘；点星 = 提到它（+0.6）；「复习全部」点亮所有。

## 首次安装会问你一句

第一次运行 `init` 时，会先介绍三层记忆，再问要不要启用记忆星图：

```
=== memblocks 首次安装 ===
三层记忆已就绪：稳定区 / 待办 / 归档

另外它还有一个「记忆星图」：把记忆画成会变暗的星，
点一下就重新变亮，用来直观看到哪些事快被忘记了。

是否启用记忆星图？[y/N]
```

- 非交互环境（脚本、CI）不会卡住，默认不启用并提示后续怎么开
- 也可以直接用参数：`init --star` / `init --no-star`
- 之后随时改：`config --star on|off`，`config --show` 看当前配置
- 选择记在 `config.json`，只问一次

### 引导的边界（都测过）

| 场景 | 行为 |
| --- | --- |
| 全新安装 | 询问一次 |
| 已有记忆的老用户升级 | **不再询问**，自动视为已启用过 |
| 非交互 / 脚本 | 不卡住，默认关闭并提示 |
| `--star` 与 `--no-star` 同时给 | 后者生效 |
| 配置文件损坏 | 报错退出（退出码 2），不静默重建 |
| 星图关闭时运行 star | 照常生成，但提示 `config --star on` |
| 重复 init | 不再打印横幅 |

### 目录不可写时

`init` 会明确报错并退出（退出码 2），不会留下半个配置文件：

```json
{"error": "无法创建数据目录 ...：拒绝访问。请换一个有写权限的路径（--root）"}
```

已测：父路径是文件、目录 ACL 拒绝写入、盘符不存在。

## 接入别的程序（HTTP 接口）

memblocks 本体是 Python，别的宿主（DSH、n8n、脚本）通过 HTTP 对接，不用改宿主代码：

```bash
python -m memblocks.cli serve --port 8765
```

| 接口 | 说明 |
| --- | --- |
| `POST /inject` | `{"query":"...","max_tokens":800}` → 注入文本 |
| `POST /stable` | 加长期事实 |
| `POST /todo` | 加待办（支持「下周三」） |
| `POST /block` | 加归档块 |
| `POST /review` | 给相关记忆加权 |
| `GET /memories` | 列出稳定区 + 待办 |
| `GET /star` | 记忆星图 HTML |
| `GET /health` | 存活检查 |

客户端与示例：

- `integrations/dsh/README.md`：DSH 接入的三种方式（shell 工具 / Node 客户端 / AstrBot）
- `integrations/dsh/memblocks-client.mjs`：零依赖 Node 客户端

接口默认只监听 `127.0.0.1`，不对外暴露。

## 恒星：永远不会遗忘的记忆

`permanent` 标记的记忆在星图里是**金色恒星**，固定在最中心，不随模拟时间变暗：

```bash
python -m memblocks.cli stable add "用户是律师，在邹城执业" --permanent
python -m memblocks.cli stable pin   --id st-xxxx     # 把已有记忆设为恒星
python -m memblocks.cli stable unpin --id st-xxxx     # 取消
```

规则：

- 权重和亮度永远 100%，不参与遗忘
- **稳定区写满 100 条时不会被淘汰**
- 星图上是带十字星芒的金色星，位于星系中心

适合：身份、人设、长期约定这类"忘了就出大事"的事。

## 仅展示（display_only）

有些记忆只想在星图里看，不想进上下文——比如人设摘要：

```bash
python -m memblocks.cli stable add "人设摘要…" --permanent --display-only
python -m memblocks.cli stable display --id st-xxxx    # 已有记忆改成仅展示
```

行为：

| 场景 | 是否出现 |
| --- | --- |
| 星图 | ✅ 显示（金色恒星） |
| `inject` 注入上下文 | ❌ 不出现 |
| 上限淘汰 | ❌ 不参与 |

适合"我只想让它作为可视化参考，不想让它影响真实对话"的内容。

## 单击 vs 双击

| 操作 | 行为 |
| --- | --- |
| 单击星 / 列表项 | 选中，右下角显示详情 |
| **双击** | 真正"提到它"：调 `POST /api/memory/hit`，云端权重 +0.2 并落盘 |
| 双击待办 | 不生效，提示"待办不计权重" |
| 用 `file://` 打开 | 只做动画演示，不写回 |

双击后会弹出提示，例如「已记录：用户是律师… · 权重 1.2」。

写回需要星图由面板（HTTP）提供；单独打开的 HTML 是只读演示。

### 双击加权的边界（已测）

| 场景 | 结果 |
| --- | --- |
| 连续点 100 次 | 权重封顶 9.0 |
| 20 线程各点 5 次 | 精确累计，无丢失 |
| 待办 ID | 拒绝，不加权 |
| 不存在的 ID | 返回 null |
| 空 ID / 带空格 | 拒绝 |
| `abc; rm -rf /` | 拒绝（ID 白名单） |
| 超长 / 中文 ID | 拒绝 |
| 面板缓存 | 加权后自动失效，立刻能读到新值 |

ID 只允许 `A-Za-z0-9_-`、长度 ≤64，防止拼进 SSH 命令时被注入。

## 语义抽取：不再靠关键词

以前靠关键词匹配（我 / 喜欢 / 生日 / 记住）＋字数门槛，短句会被漏掉，
比如「去弄鸡翅」四个字，既不命中关键词也不够长。

现在改成三步：

```
1. 缓存：每条消息先写进 buffer.jsonl
2. 抽取：攒够 N 条（默认 5）交给模型，让它输出 JSON 事实
3. 合并：按 importance/confidence 打分入库，重复的合并加权
```

```bash
# 配置模型（只配一次）
python -m memblocks.cli config --llm-key sk-xxx --llm-model deepseek-chat --distill-min 5

# 手动喂一句话 / 手动抽一次
python -m memblocks.cli capture --text "他晚上要做鸡翅"
python -m memblocks.cli distill
```

抽出来的事实：

```json
{"text": "晚上要做鸡翅", "kind": "待办", "importance": 3, "confidence": 0.9}
```

权重 = `0.6 + 0.3×importance + 0.2×confidence`，重复事实不新增，只加权重。

### 成本

- 每批（5 条消息）约 100~200 token
- 一批只调用一次模型，均摊到每条消息很少
- 也可以换成更便宜的小模型做抽取，配置 `--llm-model` 即可

### 开关

`enable_semantic`（适配层里）控制是否自动抽取；关掉就只做注入。

## 记什么、不记什么

| 说法 | 处理 |
| --- | --- |
| 我**明天**做可乐鸡翅 | 待办（截止明天） |
| **一会**去做可乐鸡翅 | 待办（截止今天） |
| **去做**可乐鸡翅（没说时间） | 待办，约 10 天淡忘 |
| 我**做**可乐鸡翅 | 习惯（不会过期） |
| **我在做** / 刚吃完 / 今天好累 | 不记 |
| **上周刚搬完家** / 我妈做了手术 | 经历（长期保留） |

「经历」类的关键词：搬家、换工作、升学、结婚、生子、住院、手术、亲人去世、大额支出。

## 近期事件：只记三天

过去组里那两条原本「不记」的日常琐事，现在记三天：

| 说法 | 处理 |
| --- | --- |
| 昨天做了可乐鸡翅 / 刚吃完火锅 | 事件，保留 3 天 |
| 今天去了超市 / 刚见了朋友 | 事件，保留 3 天 |
| 上周去了成都 / 上个月搬完家 | 超过三天：日常不记，重要经历记「经历」 |

- 存在 `events.jsonl`，`janitor` 每天清超过 3 天的
- 注入时以【近几天】出现（最多 3 条）
- 星图上是青绿色节点

## 星图 1.7：能去重、能钻进去看

这一版把星图从"只能看"变成"能操作"：

**一键去重**
- 页面底部「去重」按钮 / `POST /api/memory/dedupe` / QQ 发 `/记忆去重`
- 稳定区里同 tag、非 protected、相似度 ≥0.82 的条目合并，权重相加（封顶 9）
- 被合并的进 `archive.jsonl`，可追溯
- `janitor` 每天也会跑一遍，防止再长出重复

**点星聚焦**
- 点一颗星 →「只看它的星系」，只画它和邻居
- 1 跳 / 2 跳 切换，`Esc` 回全景

**360° 旋转**
- 拖拽左右转水平角、上下调俯仰角，不会卡在极点
- 拖拽超过 6 像素不算点选，转的时候不会误触

**更好读**
- 文字单独一层，加描边阴影，星星再亮也不糊字
- 中心光晕收敛，恒星亮度下调
- 滚轮缩放上限 8 倍，下限 0.35

**更立体**
- 每颗星有随机的三维轨道平面，不再是一张扁盘
- 约 38% 逆时针，其余顺时针（每次刷新随机）

**无面板也能看**
```bash
python -m memblocks.cli --root <记忆目录> serve --port 8765
```
`GET /star`、`POST /api/memory/hit`、`POST /api/memory/dedupe` 都有。
